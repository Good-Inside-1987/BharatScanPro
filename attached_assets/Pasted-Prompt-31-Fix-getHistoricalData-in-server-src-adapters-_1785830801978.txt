Prompt 31 — Fix: getHistoricalData() in server/src/adapters/fyers.ts
misclassifies Fyers' s:"no_data" response as an error.

Fyers' history endpoint returns three possible values for the "s" field:
  - "ok"       — success, candles array present (possibly empty)
  - "no_data"  — valid symbol, genuinely no candles for the requested
                 range (thinly traded day, newly listed symbol, etc.) —
                 NOT an error
  - "error"    — a real rejection (invalid symbol, bad request, etc.)

Currently the check `if (data.s !== "ok")` throws a FyersApiError for
BOTH "no_data" and "error", conflating a harmless empty result with a
genuine failure. This causes symbols that simply have no data for a date
to be retried as transient failures and logged under the "failed" bucket
in syncJobs.ts instead of the "noData" bucket, where they've always
belonged.

Fix — in getHistoricalData()'s chunk loop in server/src/adapters/fyers.ts,
change the status check to treat "no_data" as a valid empty response
(same as "ok" with 0 candles) rather than throwing:

  if (data.s === "no_data") {
    // Valid symbol, no candles for this range — not an error, just
    // nothing to report. Treat identically to "ok" with an empty array.
    continue;
  }

  if (data.s !== "ok") {
    throw new FyersApiError(
      {
        provider: "fyers",
        operation: "history",
        httpStatus: 200,
        brokerStatus: data.s,
        brokerMessage: data.message,
        request: { symbol, resolution, rangeFrom: chunk.from, rangeTo: chunk.to },
        responseBody: sanitizeResponseBody(data),
      },
      `Fyers history rejected for ${symbol} (status: ${data.s}): ${data.message || JSON.stringify(sanitizeResponseBody(data))}`
    );
  }

Place the "no_data" check immediately before the existing "!== ok" check,
inside the same chunk-loop `for` block, so it runs before the throw and
simply skips to the next chunk (or falls through to return the
accumulated — possibly empty — bars array if it's the last/only chunk).

Test: re-run EOD sync. ABNINT should now show up in the "noData" bucket
of the loop summary instead of "failed", and the job should complete
without retrying it as a transient overload.
