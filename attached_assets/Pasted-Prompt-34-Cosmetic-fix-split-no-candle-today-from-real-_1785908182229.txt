Prompt 34 — Cosmetic fix: split "no candle today" from real errors in
optionsDataService.ts's per-contract sync counter, so the "failed=" number
in logs isn't misleadingly inflated by normal untraded contracts.

Currently, in syncOptionsForUnderlying()'s per-contract loop, both a
genuinely empty response (contract just didn't trade that day — expected
and harmless) and a real thrown error both increment the same `failed`
counter, making the log line look far worse than it actually is.

1. Update the UnderlyingSyncResult interface to track them separately:

interface UnderlyingSyncResult {
  completed: number;
  noData: number;
  failed: number;
  budgetExhausted: boolean;
  rateLimited?: boolean;
}

2. In the per-contract loop, split the branches:

  let completed = 0;
  let noData = 0;
  let failed = 0;
  let budgetExhausted = false;

  for (const item of items) {
    if (!checkAndConsumeBudget()) {
      budgetExhausted = true;
      break;
    }
    try {
      const bars = await throttleCall(() => adapter.getHistoricalData(item.symbol, "1", date, date));
      upsertOptionsBars(uName, expiry, item.strike, item.type, bars);
      if (bars.length > 0) {
        completed++;
      } else {
        // No candle for this date (e.g. contract didn't trade) — not a
        // failure, just nothing to report.
        noData++;
      }
    } catch (err) {
      failed++;
      console.error("[optionsDataService] ✗ %s: %s", item.symbol, err instanceof Error ? err.message : String(err));
    }
  }

  return { completed, noData, failed, budgetExhausted };

3. Update syncOptionsForNightly() (the outer loop aggregating across
underlyings) to track a running `noData` total alongside `completed` and
`failed`, and include it in the final summary log and finishSyncLog stats:

  let completed = 0;
  let noData = 0;
  let failed = 0;
  let skippedBudget = 0;
  ...
  completed += result.completed;
  noData += result.noData;
  failed += result.failed;
  ...
  const stats = { completed, noData, skippedBudget, failed };
  ...
  console.log(
    "[optionsDataService] Nightly options sync done — completed=%d noData=%d skippedBudget=%d failed=%d",
    completed, noData, skippedBudget, failed
  );
  return stats;

4. Update the function's outer return type and the top-level function's
own return type/signature (and any callers that destructure { completed,
failed, skippedBudget } from syncOptionsForNightly) to also include
noData, so nothing silently drops the new field. Search the file for all
call sites of syncOptionsForNightly and syncOptionsForUnderlying to catch
any TypeScript type errors from the added field.
