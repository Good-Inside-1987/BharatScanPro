Prompt 28 — Fix: broker-connections calls and two DataContext startup
fetches are missing the Authorization Bearer header, causing "Unauthorized"
on broker connect/save even when the user is properly logged in.

Root cause: server/src/index.ts's /api auth gate accepts either a Bearer
token (Authorization header) or the bs_session cookie. Every page that goes
through artifacts/bharatscan/src/lib/api.ts's request() helper correctly
sends the Bearer token from localStorage ("bs_auth_token") and works fine.
But three call-sites bypass that helper and rely only on the cookie, which
is not reliably persisted/sent in this Electron/dev environment:

1. artifacts/bharatscan/src/pages/Settings.tsx — the local brokerFetch()
   helper (used for ALL broker connection calls: create, connect,
   disconnect, delete, auth-url) does not attach an Authorization header.

2. artifacts/bharatscan/src/context/DataContext.tsx — two raw fetch() calls
   inside useEffect hooks (one fetching "/api/market-data/scanner/universe-data",
   one fetching "/api/market-data/scanner/options-universe-data") also send
   no Authorization header.

Fix part 1 — Settings.tsx: update brokerFetch() to read the token from
localStorage ("bs_auth_token") and attach it as a Bearer header, matching
the pattern already used in api.ts's request(). Also dispatch the existing
"auth:unauthorized" CustomEvent on a 401 response so LoginGate reacts
consistently, same as api.ts does.

async function brokerFetch<T>(path: string, init?: RequestInit): Promise<T> {
  const token = (() => {
    try { return localStorage.getItem("bs_auth_token"); } catch { return null; }
  })();
  const authHeader: Record<string, string> = token ? { "Authorization": `Bearer ${token}` } : {};
  const res = await fetch(path, {
    ...init,
    headers: { "Content-Type": "application/json", ...authHeader, ...(init?.headers ?? {}) },
    credentials: "include",
  });
  if (res.status === 401) {
    window.dispatchEvent(new CustomEvent("auth:unauthorized"));
  }
  const json = await res.json();
  if (!res.ok) throw new Error((json as { error?: string }).error ?? `HTTP ${res.status}`);
  return json as T;
}

Fix part 2 — DataContext.tsx: update both raw fetch() calls (loading
cached market data and cached options data on mount) to attach the same
Bearer header, e.g. extract a small local helper:

function authedFetch(path: string): Promise<Response> {
  const token = (() => {
    try { return localStorage.getItem("bs_auth_token"); } catch { return null; }
  })();
  const authHeader: Record<string, string> = token ? { "Authorization": `Bearer ${token}` } : {};
  return fetch(path, { headers: authHeader, credentials: "include" });
}

...and replace:
  const res = await fetch("/api/market-data/scanner/universe-data");
with:
  const res = await authedFetch("/api/market-data/scanner/universe-data");

...and replace:
  const res = await fetch("/api/market-data/scanner/options-universe-data");
with:
  const res = await authedFetch("/api/market-data/scanner/options-universe-data");
