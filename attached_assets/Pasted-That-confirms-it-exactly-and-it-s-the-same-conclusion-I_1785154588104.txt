The fix, concretely

Two places need to change in liveFeedService.ts:

1. rankFoSymbolsByPrice() — currently selects the bare s.symbol. Change to prefer fyers_symbol:

sql
SELECT s.symbol AS symbol,
       COALESCE(s.fyers_symbol, s.symbol) AS resolved_symbol,
       latest.close AS price
  FROM symbols s
  JOIN (...) latest ON latest.symbol = s.symbol
 WHERE s.is_fo_eligible = 1
   AND latest.close IS NOT NULL
 ORDER BY latest.close ASC

Then use resolved_symbol (not symbol) as what gets passed into subscribeSymbols().

2. toFyersSymbol() — right now it's a dumb fallback that assumes -EQ. Once callers are passing the already-correct fyers_symbol (which already contains NSE:...-SM, NSE:...-BE, etc. — i.e. already contains :), this function's includes(":") branch will just pass it through unchanged, which is correct. The only remaining risk is other call sites that still pass bare tickers without going through fyers_symbol (e.g. any ad-hoc chart-view subscribe from the frontend) — worth a quick grep for other callers of subscribeSymbols( to confirm none of them are constructing bare symbols independently.
