Prompt 30 — Fix: FyersApiError still masks the real reason when Fyers
returns HTTP 200 with a JSON-level rejection (`{s:"error"}`) that has an
empty/missing `message` field. This is the exact same masking bug as
Prompt 29, but in a different branch — the `data.s !== "ok"` checks in
server/src/adapters/fyers.ts, not the `!response.ok` branch already fixed.

There are four call sites, all with the identical pattern — none pass an
explicit `message` to the FyersApiError constructor, so when
`data.message` is empty, the constructor's hardcoded default "Fyers REST
request failed" is used instead, discarding `data.s` (brokerStatus) and
the response body even though both are already captured in `details`.

gets logged) always includes the real brokerStatus and a body preview,
